# SCAN 任务梳理模板

> 用途：在需要规划的多阶段任务开始时，明确目标、验收、范围、依赖和验证路径。模式及是否建立状态见 `../SKILL.md` §2、§3、§7。模板不是新增流程门槛，小任务按需精简。

## 对话输出

standard/team 在执行业务步骤前输出下列四项；这也是初始化状态/日志的规划摘要。只做内部规划、写任务列表或只写文件不算完成对话输出。

```text
SCAN
S（Scope）｜<目标、范围、约束；已有改动与假设>
C（Criteria）｜<可观察判据、来源和验证方法>
A（Actions）｜<步骤、依赖、串并行及写域>
N（Next）｜<立即下一步、阻塞与恢复路径>
```

## 梳理项

| 项目 | 内容 |
|---|---|
| 目标 | <忠实摘要用户目标；必要时记录目标原话> |
| 验收 | <用户明确的判据；区分必要推导与用户要求> |
| 范围 | <要改/检查的目标；明确不做项或限制> |
| 步骤 | <关键步骤及其依赖；指出可并行部分> |
| 写域 | <并行时为每项标明文件/目录；同一文件同一时刻一个写者> |
| 团队 | <独立任务可用平台支持的团队；不支持或无适用成员时串行执行> |
| 验证 | <可能有价值的基线、针对性检查和验收证据> |
| 风险与阻塞 | <未知项、权限或需用户决定事项> |
| 下一步 | <开始执行的具体动作> |

## 协作任务清单示意

以下是虚构示例，不表示已派发或已验证：

| 任务 | 目标/写域 | 依赖 | 验收证据 |
|---|---|---|---|
| 实现校验函数 | `src/validators/email.ts` | 无 | 实际运行相关单测 |
| 接入表单 | `src/components/LoginForm.tsx` | 校验函数签名确定后 | 实际运行表单测试 |
| 补充测试 | `tests/validators/email.test.ts` | 接口确定后 | 测试运行结果 |

## 完成梳理

- 目标与验收条件可区分；没有替用户擅自增加目标。
- 多阶段任务的步骤、依赖及写域清楚；存在冲突时先串行化。
- 只计划对决策或验收有价值的检查；改动前基线适用于任务时再运行。
- 清楚记录哪些内容是待确认、待执行或尚未验证。
