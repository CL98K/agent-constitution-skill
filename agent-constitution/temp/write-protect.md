# 写入前核对与并发保护

> 用途：处理任务范围、已有文件编辑、并发写入与误覆盖风险。行为原则见项目 `AGENTS.md`；任务执行机制见 `../SKILL.md` §3、§6、§7。不要依赖环境变量凭据或递归 audit 日志。

## 写入前

- 明确文件属于用户请求范围；新增或扩大范围时按主 Skill 处理。
- 修改前读取相关文件或相关区段，依据当前内容编辑；大文件不要求无关全文读取。
- 查询并发编辑风险；同一文件同一时刻只能有一个活跃写者。跨会话或长间隔后，在写前重读受影响区段并确认上下文仍成立。
- 区分可恢复编辑与高影响/不可逆操作。授权取决于操作语义和后果，而非采用增量编辑还是整文件写入的工具形式。
- 不因合法删行、重组或内容精简而自动拒绝修改；数量变化只是提示，结合上下文检查是否遗漏或误删。

## 执行中

- 尽量保持改动聚焦，避免覆盖无关内容；重写文件时确认载荷包含预期内容。
- 发现并发变化时停止基于旧上下文的写入，重新读取、核对差异并再编辑。
- 若误改或遗漏，优先基于当前内容恢复相关部分；不得覆盖并发产生的用户修改。
- 常规清理仅限本任务产生、身份明确且不再需要的临时产物；不要批量删除或回滚无关文件和改动。用户明确点名删除既有目标时，视为该目标的授权，但仍核对文件身份、范围及不可逆影响；批量或不可恢复且有歧义时先澄清。

## 写后核对

- 回读受影响区段或相关产物，确认实际内容、目标范围与引用关系正确。
- 按任务需要运行针对性验证；记录命令原文和真实结果。未运行要明确说明原因。
- `standard` / `team` 模式在状态或日志中记录有价值的改动摘要与 diff/命令证据；不要求每次编辑写递归审计明细。

## 示意例

以下仅为虚构示意，不是实际文件状态：

```text
编辑前｜已读取目标函数及相邻调用点
并发核对｜重读后内容未变化
编辑后｜仅修改目标函数
验证｜相关测试未运行，原因：测试依赖未安装
```

## 注意

状态文件身份冲突、状态恢复、目标切换和文件路径均遵从 `../SKILL.md` §7；本文件不另行定义命名、身份或 schema。涉及安全授权或高影响行为时按项目 `AGENTS.md` 与主 Skill 暂停处理。
