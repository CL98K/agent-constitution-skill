# 任务进度日志模板

> 用途：为 `standard` 与 `team` 任务追加记录关键进展、验证证据和目标变更。日志应简洁并追加写入；无需每轮写日志或记录递归 audit。字段语义和主状态 schema 见 `../SKILL.md` §7。

## 记录格式

按需要采用一条或多条：

```text
时间｜<含时区的时间>
类型｜scan / progress / verification / decision / exception / objective-switch / final
目标或验收变化｜无 / <变化及依据>
完成｜<已完成工作>
验证证据｜<实际命令及结果；或未验证及原因>
团队｜无变化 / <任务分配或成员回报>
风险与阻塞｜无 / <事实及影响>
状态｜<相关 state / flow 变化及原因>
下一步｜<行动或待用户决定>
```

日志不是状态 schema 的替代品：当前状态写入状态文件，日志记录有意义的过程与证据。只有实际执行的命令才记录为已运行；不要声称模板示例输出是真实结果。

## 初始化示意

```text
2026-11-15T23:00:00+08:00｜scan
目标或验收变化｜无
完成｜已明确任务范围与可观察验收条件
验证证据｜未运行；当前阶段仅完成范围分析
团队｜单 Agent
风险与阻塞｜无
状态｜running / unverified
下一步｜检查相关实现并决定必要验证
```

> 上述时间、任务和内容完全虚构，仅说明格式。

## 使用约定

- 只记录对恢复、决策、验收或追溯有帮助的实质变化。
- 目标切换时简要归档旧目标的验收状态与未决项，再记录新目标。
- 状态文件按需更新，不要求每次全量复制到日志。
- 不记录不存在的平台计数、轮询心跳或执行时长；平台无后台计时能力时不承诺定时汇报。
- 不把未执行的测试、设计走查或推测写成实测证据。
