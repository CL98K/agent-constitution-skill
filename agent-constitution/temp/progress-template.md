# 进度汇报模板

> 进度汇报方式与时机见 `../SKILL.md` §4、§9。没有后台计时能力时不承诺定时发送；平台事件通知优先，避免忙轮询。模板字段按任务需要精简，不要求机械套用。

## 推荐内容

```text
目标｜<忠实摘要>
已完成｜<可核对的进展>
正在做｜<当前工作；无则写无>
阻塞｜<具体事项及所需决定；无则写无>
下一步｜<明确行动>
```

`standard` 或 `team` 任务可在确有帮助时补充状态文件更新情况、验收进度和实测证据。`light` 任务通常直接回答，无需状态文件或进度块。

## 示意例

以下内容为虚构示意，不能作为实际任务证据：

```text
目标｜修复登录表单邮箱校验
已完成｜定位到提交处理函数与现有单测
正在做｜实现修复并补充边界测试
阻塞｜无
下一步｜运行相关测试并记录结果
```

## 汇报核对

- 汇报目标、已完成、正在做、阻塞和下一步，内容与当前实际状态相符。
- 有实质变化时及时汇报；无变化不为凑次数重复输出。
- 清楚区分已实施、已检查、未验证和待用户决定。
- 如平台没有定时/后台能力，不虚构检查点、倒计时或团队活动。
