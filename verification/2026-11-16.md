# agent-constitution 2.0.1 场景验证

已将主流程全部 9 节、9 份模板及 2 份参考文件映射到 30 个场景。实际执行发现问题后修正规则并回归；这不是“所有场景均已平台实测通过”。安装与自动发现尚未验证，时间、用户决策和失败成员轨迹中有明确模拟项。

## 方法与证据边界

- 首轮正常、异常试跑给出了预期判据，属于有引导演练。两次修订后独立任务只给业务需求，没有点名 SCAN 格式；执行者主动读取规则，不能视为平台自动发现。
- 故障工具为本地可控夹具，真实返回失败退出码或产生本地副作用，不访问网络、生产系统或真实凭据。
- 持久化状态由 PyYAML 6.0.3 实际解析；业务测试由 Python unittest 独立重跑。人工语义走查与命令检查分别记录。
- 证据包目录名为 `constitution-verification-20261116`，含场景矩阵、原始试跑报告、故障计数、失败快照、独立输出和校验脚本。该证据包单独交付，不作为已安装 Skill 的运行资源。

## 发现与修复

| 发现 | 实际表现 | 修复与回归 |
|---|---|---|
| SCAN 可见性和时机不明确 | 首轮即使提示判据，仍在实现前漏输出 | [主流程 §3](../agent-constitution/SKILL.md#3-scan先确定目标证据和执行路径) 明确业务动作前对话输出 S/C/A/N，模板和自检同步；后续两个独立任务均先输出再写业务文件 |
| 时间标量自动转型 | 原状态示例及正常试跑的未加引号时间被解析为 datetime，违反字符串 schema | 模板时间加引号；严格检查最终类型，保留原始失败快照 |
| 特殊字符串与缩进易破坏结构 | 冒号列表项被解析为映射；另一回归任务曾出现 YAML ParserError | [状态规则](../agent-constitution/SKILL.md#7-状态与日志唯一字段定义源) 增加安全序列化及实际解析回读；允许 JSON 对象作为 YAML 内容；修复后重新解析 |
| 缺依赖示例容易诱导无谓询问 | 示例缺少“安装需要新增授权”的前提 | [异常模板](../agent-constitution/temp/safety.md) 区分授权内可逆修复与改变共享环境；人为缺失模块试跑采用标准库替代，无安装请求 |

另发现验证过程错误，已保留并修复：校验器曾静默跳过不能解析/非围栏格式的状态，现对指定状态强制解析、缺字段或解析失败均返回非零；故障试跑把模拟重派数写入真实 `retry_total`，已改回实际值 0，模拟轨迹独立保留。主验证任务的状态/日志也未及时更新，最终只追加实际收口记录并保留 `flow=fail`。这些执行错误不通过补写记录追溯改判成功。

## 最终独立检查

- 正常场景：9 项测试，8 通过、1 项预置失败；退出码 1 符合该夹具判据，不能写成“全测通过”。
- 首个独立回归：5 项业务测试通过；SCAN 时机正确，但初次状态存在冒号类型错误，保留 `flow=fail`，修复后解析通过。
- 故障夹具计算：2 项测试通过；四种故障调用数分别为 3、3、1、1。
- 特殊字符串独立回归：5 项测试通过；状态初次解析失败后在交付前修复，最终解析通过，日志保留失败。
- 严格结构与产物检查：74 项通过、0 项失败。此数字是脚本检查条目数，不是 74 个业务场景或模型遵循成功次数。
- `run_checks.py` 独立运行退出 0；Git 空白检查另以 `git diff --check` 核对。

复核入口为证据包中的 `run_checks.py`（调用 `validate.py`）。当前脚本保留本次机器路径，是本次证据复核工具，不作为跨平台测试框架发布。复核需要 Python 与 PyYAML；不要重跑 `setup.py` 或故障注入来覆盖首轮证据。

## 仍需验证

实际平台安装/发现、真实失败成员重派、平台事件等待与长时恢复，以及不同模型/平台的重复抽样均未完成。现有规则已覆盖这些场景的处理方式，本次只取得其中部分的模拟证据。Markdown 指令依赖宿主和模型执行；本次已观察到真实遗漏，不能承诺“严格遵循永不漏项”。需要强制保证时，应由平台权限、状态校验和 CI/独立验收提供门禁。
